Exercise device auth, the hardware voice protocol, and the concurrency fix - no curl required

Device auth vs. CSRF

Sends a text query with the API key above (should succeed with no CSRF token), then repeats it with a deliberately wrong key (should be rejected with 401, not the browser's generic 403).

Binary hardware protocol

Sends a short synthetic test tone (not real speech - the tutor will likely just ask you to repeat, that's expected) to /api/v1/voice/query with Accept: application/x-tutor-voice, then parses the framed binary response in the browser exactly the way firmware would: a 4-byte length, a JSON metadata block, then one or more length-prefixed WAV frames you can play below.

Concurrency (event loop not blocked)

Starts a voice request (which takes a few seconds), and shortly after, fires a /api/v1/health check while the voice request is still running. Before the fix, health would have queued behind the voice request; now it should come back almost instantly regardless.
